ADC Output Diagnosis

FFT · spurs · interleaving mismatch · sparkle codes · noise · DNL / INL

No AI and no trained model, only fixed signal-processing rules. Everything runs in your browser, and your data is never uploaded.

ADC output data

Example data

One value per line (output code or voltage), in sampling order. Two columns (time, value) also work; the last column is used. You can also drop a file onto the box. The input must be a single sine wave. The example is an 8-channel, 10-bit, 6.4 GS/s interleaved ADC with several faults added on purpose. You can also load raw comparator bits: one string of 0/1 per line, MSB first, which suits SARs with redundancy.

Settings

For an ordinary ADC, set M to 1. For an interleaved ADC, set M to the number of channels. Example: with 8 phases × 4 sub-ADCs, use 8 to compare the phases, or 32 to see every sub-ADC.

Values accept SI prefixes: 6.4G, 985.9M, 10n.

SAR capacitor-mismatch estimate

No data needed. Enter the unit-capacitor mismatch; many random capacitor arrays are generated to show how bad DNL, INL and ENOB can get. Useful for choosing the unit-capacitor size.

How it works

There is no AI involved. Every result comes from fixed rules about how ADCs behave, so the same data always gives the same answer.

  1. Run an FFT and find the signal and the largest spurs. Then look at where each spur sits:
    at multiples of fin (folded back above Fs/2) → harmonics, circuit nonlinearity;
    at k·Fs/M → channel offset mismatch;
    at k·Fs/M ± fin → channel gain or timing mismatch.
  2. Fit a sine wave (one per channel for an interleaved ADC). The DC term is the offset, the amplitude is the gain, and the phase is the sampling instant. Comparing each channel with the average gives its mismatch.
  3. Subtract the fitted sine from every sample. A sample whose error is more than 7 times the typical error counts as a sparkle code. The typical error is the channel's noise.
  4. Compare the noise with ideal quantization noise (0.29 LSB rms), and check whether the noise floor rises next to the signal or at low frequency.
  5. Count how often each output code appears (code histogram) and compare it with what an ideal sine would give. This gives DNL and INL.
  6. SAR bit weights: in a plain binary SAR, each binary digit of the output code is one comparator decision. A least-squares fit of these 0/1 bits together with a sine gives the true weight of each bit.
  7. Remove each problem from the data and recompute SNDR, to show which fix is worth the most.

Needs a single-tone sine input, ideally with coherent sampling (input frequency = prime × Fs / N). An interleaved ADC needs at least 16 samples per channel. DNL / INL needs integer output codes and roughly 10 or more samples per code.
